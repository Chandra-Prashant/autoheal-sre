# AutoHeal-SRE — Project Instructions for Claude Code

## What this is

A self-healing code repair agent. It takes a Python test failure or stack trace,
uses an AST-based call graph (not naive text chunking) to find the actual
relevant code, proposes a patch via a multi-agent LangGraph loop, runs the
patch in an isolated Docker sandbox, and only opens a PR once tests pass.

This is a solo, college-project-scale build. Scope is intentionally cut down
from a "real startup" version — see Non-Goals below. Do not add services,
abstractions, or config options beyond what's listed here unless asked.

## Why it's built this way (context for you, Claude)

- Naive RAG chunking splits functions mid-body and loses call relationships.
  We use tree-sitter to parse real function/class boundaries instead.
- LLM patches without execution feedback hallucinate APIs. We close the loop:
  patch → run in sandbox → feed real stderr back to the agent → retry (max 3x).
- Running generated code on the host is a real risk. Everything executes in a
  throwaway Docker container with no network and a memory/CPU cap.

## Scope (MVP — build this, nothing more)

- **Language:** Python only. No JS/Go support.
- **Graph:** tree-sitter-python + NetworkX, in-memory. No Neo4j.
- **Vector store:** ChromaDB, local persistent client. Not Qdrant.
- **Orchestration:** LangGraph, 4 nodes (diagnose → plan → code → verify),
  synchronous. No Celery/Redis — FastAPI background tasks are enough.
- **Sandbox:** Docker SDK for Python. `network_mode="none"`, `mem_limit="512m"`,
  30s timeout, read-only rootfs except `/workspace`.
- **Tracing:** Langfuse, free tier. Log node name, tokens, latency per run.
- **PR generation:** PyGithub, opens a real PR against a test repo.
- **Eval set:** 10–15 hand-picked bugs in a sample repo (mix of off-by-one,
  unbound variable, wrong exception type, missing null check). Track pass@1
  and pass@3 in a simple `evals/results.json`, not a formal benchmark harness.

## Non-goals (explicitly do not build these — mention as "future work" in README only)

- Multi-language support
- Neo4j / graph database server
- Celery + Redis async queue
- Full Ragas eval harness
- Streamlit/Next.js dashboard (CLI + FastAPI docs page is enough for a demo)

## Coding conventions — read this before writing any code

The goal is code that reads like it was written by one developer over a few
weeks, not generated in one pass. Concretely:

- **Comments only where they earn their place.** Explain *why*, not *what*.
  Don't add a docstring to every single function — skip it for anything
  whose name and signature already say what it does. A 3-line helper doesn't
  need a comment; a retry-loop edge case does.
- **No header/banner comments.** No `# ===== SECTION: AGENTS =====`, no
  `"""Module: ast_parser.py — handles AST parsing"""` restating the filename.
- **No AI disclosure text, no "Generated by" comments, no todo-lists dumped
  in comments.** If something's unfinished, it's just not there yet — don't
  narrate it in-code.
- **Inconsistency is normal.** Not every function needs full type hints or a
  try/except — add them where they matter (I/O, subprocess calls, external
  API calls), skip them for trivial internal helpers. Uniform, exhaustive
  coverage everywhere is the tell of generated code.
- **Naming:** short, ordinary variable names (`patch`, `trace`, `ctx`), not
  descriptive-to-a-fault (`extracted_error_traceback_string`).
- **Error handling:** handle the failure modes that actually matter for this
  project (Docker daemon not running, GitHub token missing, LLM timeout).
  Don't wrap every function body in a blanket try/except.
- **No emoji in code, commit messages, or comments.**
- **README tone:** written like a student explaining a project, not a
  product one-pager. Skip marketing language ("cutting-edge", "seamlessly").
  It's fine to mention limitations plainly ("only handles Python, single
  file bugs for now").

## Commit strategy

Build and commit in stages that reflect how this would actually get built —
don't do one giant initial commit. Roughly:

1. Repo scaffold + FastAPI skeleton, health check endpoint
2. tree-sitter AST parsing + NetworkX graph build (with a couple of test files)
3. Chroma embedding + retrieval on top of the graph
4. AgentState + LangGraph skeleton with stub nodes (no real LLM calls yet)
5. Diagnostic + Planner agents wired to a real LLM call
6. Coder agent producing unified diffs
7. Docker sandbox runner + verifier node + retry loop
8. PyGithub PR generation
9. Seed evals/bugs/ with 10-15 bugs, run the full loop end to end, fix rough edges
10. Langfuse tracing wired in
11. README + demo script

Commit messages: lowercase, imperative, specific — `add call graph builder`,
not `Implement comprehensive call graph construction module`. Some commits
should fix something from a previous commit (that's normal — don't get
everything right the first time on purpose).
